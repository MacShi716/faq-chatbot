# FAQ 데이터 수집 가이드

목표: **100건** (학사 40 · 생활 25 · 장학 15 · 기타 20)

## 1. 어디서 모으나

| 구분 | 출처 | 비고 |
|---|---|---|
| 학사 | 학과 홈페이지 공지사항, 학사규정, 교육과정표 | 공지 번호까지 기록 |
| 졸업 | 졸업요건 안내, 이수학점표 | 학번/입학년도별로 다를 수 있음 → 구분 표기 |
| 수강 | 수강신청 안내문, 학사일정 | 기간은 학기마다 바뀜 → 확인일 필수 |
| 장학 | 장학 공지, 교내·교외 장학 안내 | 금액은 개인별 차이 → 일반 기준만 |
| 생활 | 생활관(기숙사) 안내, 학생회관, 셔틀버스 시간표 | 운영시간 변동 잦음 |
| 유학생 | 유학생지원팀 안내, 출입국 사무소 안내 | 비자·체류 관련은 반드시 원문 링크 |

## 2. 어떤 질문을 모으나

1. 유학생 10명 이상에게 "학과 생활에서 가장 자주 물어보는 것"을 인터뷰·설문한다.
2. 실제로 들은 표현을 **그대로** 적는다 (예: "휴학 신청은 언제 해요?").
3. 같은 뜻의 다른 표현을 3~5개 만든다 (존댓말/반말, 축약, 오타 포함).
   - `휴학 신청은 언제 해요?|휴학 언제까지 신청해요|쉬는 거 어떻게 신청해요|휴학 절차`
4. 중국어 표현은 1~2개. 중국인 팀원(***)이 검수한다.
   - `什么时候可以申请休学？|休学手续怎么办`

## 3. 답변 작성 규칙

- **확인한 내용만** 쓴다. 추측·기억으로 쓰지 않는다.
- 답변은 3문장 이내. 핵심(기간·장소·서류·링크)만 남긴다.
- `answer`(한국어)를 먼저 쓰고, 같은 내용을 `answer_zh`(중국어)에 옮긴다. 금액·날짜·건물명 같은 숫자와 고유명사는 반드시 대조한다.
- `answer_zh` 를 비워 두면 中文 화면에서 한국어 원문이 `（韩语原文）` 표시와 함께 나온다. 틀린 번역보다 낫지만, 발표 전에는 채우는 것을 원칙으로 한다.
- 확인하지 못했으면 `[작성 필요]` 로 남기고 커밋하지 않는다.
- `source` 예시: `학과 공지 2026-12호`, `학사규정 제15조`, `생활관 홈페이지`
- `checked_at` 은 **실제로 확인한 날짜** (`2026-10-25`). 오늘 날짜를 습관적으로 넣지 않는다.
- 규정이 바뀌면 `checked_at` 만 갱신하고, 답변이 달라졌으면 내용도 고친다.
- `tags` 는 **한국어와 중국어를 섞어 5~10개**. 학생이 실제로 칠 법한 명사만 넣는다
  (예: `공학관|工学馆|제1공학관|第一工学馆|건물|楼`). 동사·조사·"어디" 같은 범용어는 넣지 않는다.
  태그가 질문에 그대로 들어 있으면 유사도와 무관하게 후보로 올라오기 때문에, 너무 흔한 단어를 넣으면 오답이 늘어난다.

## 4. 품질 체크리스트 (커밋 전)

- [ ] `id` 가 중복되지 않는다
- [ ] `question_ko` 변형이 3개 이상이다
- [ ] `question_zh` 가 1개 이상이다
- [ ] `answer` 에 `[작성 필요]` 가 남아 있지 않다
- [ ] `answer_zh` 가 채워져 있거나, 비어 있음을 팀이 인지하고 있다
- [ ] `source` 와 `checked_at` 이 채워져 있다
- [ ] CSV 가 UTF-8 로 저장되었다 (Excel 로 열면 깨질 수 있음 → VS Code 사용 권장)

## 5. 검증 방법

```bash
python selftest.py          # 스키마·검색 동작 확인
python evaluate.py          # 정확도 측정
```

`evaluate.py` 의 오답 목록은 **FAQ 를 보강할 목록**이다. 오답 상위 20건을 보고
①답변이 틀렸는지 ②질문 표현이 부족한지 ③임계값이 문제인지로 나눠 분류한다.
